# Почта: письма с кодом входа

Приложение отправляет одно письмо — код и ссылку для входа хоста. Способ отправки выбирает `MAIL_PROVIDER`:

| `MAIL_PROVIDER` | Как отправляется | Для чего |
|---|---|---|
| `log` | Никак: письмо пишется в лог бэкенда | Локальная разработка (по умолчанию в профиле `local`) |
| `smtp` | Через любой SMTP-сервер: Gmail, Яндекс, почта компании | Небольшие объёмы, свой почтовый сервер |
| `resend` | Через API сервиса Resend со своего домена | Продакшен |

Другое значение остановит сервер при старте с сообщением `MAIL_PROVIDER must be log, resend or smtp`.

## Переменные SMTP

| Переменная | По умолчанию | Что это |
|---|---|---|
| `SMTP_HOST` | — | Адрес сервера, например `smtp.gmail.com`. Без него письма не отправляются |
| `SMTP_PORT` | 587 (для `ssl` — 465) | Порт |
| `SMTP_SECURITY` | `starttls` | `starttls` — обычное соединение, которое обязательно переходит на TLS (порт 587); `ssl` — TLS с первого байта (порт 465); `none` — без шифрования, только для сервера на этой же машине |
| `SMTP_USERNAME` | — | Логин. Пусто — сервер вход не спрашивает |
| `SMTP_PASSWORD` | — | Пароль. Для Gmail — пароль приложения |
| `SMTP_TIMEOUT` | `10s` | Сколько ждать соединения и ответа |
| `MAIL_FROM` | `Inside Joke <login@insidejoke.app>` | Отправитель в формате `Имя <адрес>` |

При `starttls` и `ssl` приложение проверяет, что сертификат выдан именно этому серверу.

## Gmail

Подходит, чтобы быстро начать и для небольших объёмов. Лимит обычного Gmail — около 500 получателей в сутки,
у Google Workspace — около 2000; после превышения отправка останавливается до конца суток. Для запуска на реальных
пользователей лучше Resend со своим доменом (см. ниже).

### 1. Включите двухэтапную аутентификацию

Обычный пароль Google по SMTP больше не принимает: нужен пароль приложения, а он доступен только при включённой
двухэтапной аутентификации.

1. Откройте [myaccount.google.com](https://myaccount.google.com) → **Безопасность** (Security).
2. **Двухэтапная аутентификация** (2-Step Verification) → включите и пройдите настройку.

### 2. Создайте пароль приложения

1. Откройте [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) (или **Безопасность** →
   **Двухэтапная аутентификация** → внизу **Пароли приложений**).
2. Введите название, например `Inside Joke`, и нажмите **Создать**.
3. Скопируйте 16 букв. Google показывает их один раз. Пробелы между группами можно не убирать: для Gmail приложение
   убирает их само.

Если пункта «Пароли приложений» нет: двухэтапная аутентификация не включена, аккаунт использует только ключи
безопасности (Advanced Protection), или это аккаунт Google Workspace, где администратор запретил такие пароли.

### 3. `.env`

```bash
MAIL_PROVIDER=smtp
MAIL_FROM=Inside Joke <you@gmail.com>
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_USERNAME=you@gmail.com
SMTP_PASSWORD=abcd efgh ijkl mnop
```

- `SMTP_USERNAME` — полный адрес Gmail.
- `MAIL_FROM` — **тот же адрес** (или псевдоним, добавленный в Gmail как «Отправлять письма как»). Другой адрес Gmail
  молча заменит на адрес аккаунта.
- `APP_PUBLIC_URL` — на него ведёт ссылка «Войти на этом устройстве» в письме.

### 4. Перезапустите бэкенд

`.env` читается только при старте. В логе должна появиться строка:

```
Sign-in emails go through SMTP smtp.gmail.com:587 (STARTTLS, as you@gmail.com)
```

### 5. Проверьте

1. Откройте страницу входа, введите свой адрес и нажмите **Получить код**.
2. Письмо должно прийти за несколько секунд. Копия появится в папке **Отправленные** этого Gmail.
3. Если письма нет — смотрите в логе бэкенда строку `Sign-in email could not be sent: …` и таблицу ниже.

### Если не работает

| В логе | Причина и что делать |
|---|---|
| `SMTP login failed: 535-5.7.8 Username and Password not accepted` | Неверный пароль приложения или логин. Создайте новый пароль приложения; логин — полный адрес |
| `SMTP login failed: 534-5.7.9 Application-specific password required` | Указан обычный пароль Google. Нужен пароль приложения (шаг 2) |
| `SMTP sending failed: Couldn't connect to host, port: smtp.gmail.com, 587` | Порт закрыт сетью, файрволом или антивирусом. Попробуйте `SMTP_SECURITY=ssl` и `SMTP_PORT=465` |
| `…PKIX path building failed…` или ошибка сертификата | Антивирус проверяет почту и подменяет сертификат. Отключите в нём проверку исходящей почты или добавьте исключение для Java |
| `550 5.4.5 Daily user sending limit exceeded` | Исчерпан суточный лимит Gmail. Ждите сутки или переходите на Resend |
| `SMTP_HOST is not configured` | `MAIL_PROVIDER=smtp`, но адрес сервера не задан |
| Письмо отправлено, но попало в спам | Для личного Gmail это бывает. Отметьте «Не спам»; для продакшена — свой домен и Resend |

## Другие почтовые сервисы

Настройка такая же, отличаются адрес и порт. Почти все крупные сервисы тоже требуют отдельный пароль приложения,
а не обычный пароль. Проверьте актуальные значения в справке сервиса.

| Сервис | `SMTP_HOST` | Порт и защита |
|---|---|---|
| Яндекс Почта | `smtp.yandex.ru` | 465 и `ssl` (или 587 и `starttls`) |
| Почта Mail.ru | `smtp.mail.ru` | 465 и `ssl` |
| Свой сервер | его адрес | как настроено; `none` — только если сервер на этой же машине |

## Resend

Отправка через API со своего домена, с подписью DKIM и SPF. Лучший вариант для продакшена.

1. Зарегистрируйтесь на [resend.com](https://resend.com), в **API Keys** создайте ключ с правом **Sending access**.
2. Для быстрой проверки подойдёт отправитель `onboarding@resend.dev`, но он доставляет письма только на адрес
   владельца аккаунта Resend.
3. Для реальных пользователей: **Domains** → **Add Domain** (лучше поддомен, например `mail.ваш-домен.com`), добавьте
   у DNS-провайдера показанные записи (DKIM, SPF, MX), нажмите **Verify**. Добавьте и DMARC — Resend его не создаёт.
4. `.env`:

```bash
MAIL_PROVIDER=resend
RESEND_API_KEY=re_...
MAIL_FROM=Inside Joke <login@mail.ваш-домен.com>
```
