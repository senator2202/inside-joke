# Changelog

Все значимые изменения Inside Joke. Формат — [Keep a Changelog 1.1.0](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning 2.0.0](https://semver.org/lang/ru/). Как выбирается номер версии и как выпускается
релиз — в [docs/VERSIONING.md](docs/VERSIONING.md).

Продукт до публичного запуска, поэтому версии `0.y.z`: изменения, ломающие API, протокол или конфигурацию, поднимают
MINOR и помечены **Breaking**. Версия `1.0.0` выйдет с публичным запуском.

## [Unreleased]

### Added
- Модульные тесты правил игры (blueprint, раздел 14): лобби и права ролей, анкета и секреты, выбор раунда и
  запасной контент, дуэли, «Кто из нас», «Правда или AI», паузы и переподключения, финал и «Сыграть ещё», зрители,
  реплики ведущего, жизненный цикл комнаты, что видит каждая роль; модульные тесты AI-шлюза (повтор при невалидном
  ответе, бюджеты комнаты, учёт стоимости). `GameHarness` запускает настоящий движок без Spring: фальшивый AI,
  часы и таймеры под управлением теста, фоновая работа на потоке теста, случайность с зерном.
- Покрытие кода (JaCoCo): отчёт модульных тестов и общий; фаза `test` падает, если модульные тесты покрывают пакет
  `game` меньше чем на 90 % строк или 75 % ветвлений.
- `docs/ROADMAP.md` — открытые вопросы: инженерный аудит, аудит безопасности, SOLID, горизонтальное масштабирование;
  приоритеты, признаки готовности и статус каждого пункта (✅ сделано, 🟡 частично, ⬜ открыто).
- CI на GitHub Actions (`.github/workflows/ci.yml`): `./mvnw verify` и сборка образа на каждый push в `main` и
  `develop` и на каждый pull request; отчёты тестов и покрытия — в артефактах запуска (дорожная карта, R1).
- Образ Docker: многоэтапный `Dockerfile` (сборка на JDK 21 и Node.js 22, запуск на JRE 21 от непривилегированного
  пользователя, размер кучи — от лимита памяти контейнера) и `.dockerignore`; `docker compose --profile app up`
  поднимает приложение вместе с базой (R2).

### Changed
- Тестовая пирамида: модульных тестов бэкенда 205, интеграционных 119 (было 81 и 135). Правила из `GameRulesIT` и
  `SecretsBudgetIT` проверяются модульно; в интеграционных тестах остались стыки (кадры WebSocket, записи в БД).
- Случайность игры (пары в дуэлях, «правда или выдумка», выбор ведущего) берётся из внедряемого генератора, чтобы тест
  мог воспроизвести партию. Поведение не изменилось.
- Фронтенд-тесты идут в пуле Vitest `vmThreads`: 5 секунд вместо 15.

### Fixed
- Если финальные титулы от AI опоздали и на экране уже запасные, поздний ответ AI больше не подменяет показанные
  титулы и речь. Если AI ответил ошибкой ещё во время последнего раскрытия, финал показывается сразу, без пяти секунд
  «Ведущий готовит награды…».
- Запрос, который телефон повторно отправил после обрыва связи, больше не выполняется дважды. Раньше секрет,
  отправленный в момент обрыва, мог попасть в досье два раза (и дважды израсходовать лимит и проверку модерацией),
  а голос засчитывался, но игрок видел ошибку «You already voted». Сервер помнит последние 16 запросов каждого
  участника и на повтор с тем же `reqId`, типом и данными отвечает сохранённым ответом; если первый запрос ещё
  выполняется, ответ придёт в новое соединение.
- Клиент начинает `reqId` со случайного префикса, поэтому перезагруженная страница не повторяет id прежней.
- `./mvnw` запускается в macOS и Linux: у файла в репозитории не было флага исполнения.

### Security
- Лимиты по IP за Cloudflare снова у каждого клиента свои: сети публичных прокси задаются в `APP_TRUSTED_PROXIES`
  (CIDR через запятую; готовое значение для Cloudflare — в `.env.example`). Клиент — первый адрес справа в
  `X-Forwarded-For`, не принадлежащий известному прокси, поэтому адрес, подставленный клиентом, не помогает обойти
  лимиты. Раньше за Cloudflare все клиенты получали его адреса (аудит, пункт 8; дорожная карта, R5.1).
- У пароля БД больше нет значения по умолчанию вне профиля `local`: без `DATABASE_PASSWORD` сервер останавливается
  при запуске, а не подключается с `insidejoke` (дорожная карта, R3). Перед обновлением проверьте, что переменная
  задана на сервере.
- `MAIL_PROVIDER=log` вне профиля `local` останавливает запуск: этот режим пишет в лог действующие коды входа (R4).
- Игрок больше не может закрыть блок `<player_data>` в запросе к модели своим текстом: `<` и `>` в данных игроков
  передаются как `\u003c` и `\u003e` (аудит, пункт 9).

## [0.8.2] — 2026-09-24

Внутренняя переработка ядра по инженерному аудиту (`docs/ENGINEERING_AUDIT.md`, находки S1, D2–D5 и паттерны). API,
протокол, схема БД и поведение не менялись.

### Changed
- Модули больше не зависят друг от друга по кругу. Игра объявляет порт `GameAccessPort`, биллинг его реализует;
  удаление аккаунта публикует `AccountDeletedEvent`, на который биллинг (отзыв пассов, в той же транзакции) и игра
  (закрытие комнат, после фиксации) подписаны сами; `Language` переехал в `common`.
- Команды WebSocket — таблица `CommandType → CommandHandler` вместо `switch` по строкам на 121 строку (Command);
  завершение фазы по «дальше» и по таймеру — таблица `Phase → PhaseHandler` вместо двух одинаковых `switch` (State).
- Обработчики фаз работают через интерфейс `GameRuntimeService`: не читают полей координатора, не вызывают друг друга
  цепочками, зависимости получают явно; координатор собирает их в `@PostConstruct`, подавление `this-escape` убрано.
  `RoomProjectionService` больше не зависит от координатора; метод `roundView` (199 строк, 49 ветвлений) разделён по
  видам раундов.
- Состояние игры инкапсулировано: у `RoomState`, `PlayerState`, `RoundState`, `DuelState`, `VoteStepState` нет открытых
  полей; коллекции наружу только для чтения, изменения — методами с понятным смыслом; расчёт мест и присутствия —
  методы состояния.
- Строки заменены типами: `PurchaseStatus`, `PassLogStatus`, `PassSource`, `AdjustmentAction`, `AdjustmentStatus`,
  `PaddleEventType`, `NotAppliedReason`, `AiProvider`, набор `AiOutcome.FAILURES`; в SQL статусы подставляются из
  перечислений (`DbUtils.sql`). В сгенерированном контракте поля журнала пассов стали типизированными.
- Деньги — значение `Money` (в покупке, выручке метрик и журнала пассов), арифметика только в одной валюте.

### Added
- `ModuleDependenciesTest` (нет циклов между модулями), `MoneyTest`.
- `docs/ENGINEERING_AUDIT.md` — инженерный аудит: именование, пакеты, принципы проектирования, паттерны, тесты,
  эксплуатация, безопасность, фронтенд; оценки по областям и план.

## [0.8.0] — 2026-09-23

Устранены все отклонения из инспекции кода (`docs/CODE_INSPECTION.md`). Поведение игры не менялось; меняются адреса
API (**Breaking**), имена двух переменных окружения (старые пока работают) и схема БД (миграция V6, автоматически).

### Changed
- **Breaking:** единые имена в HTTP API — «пасс» вместо «entitlement», коллекции во множественном числе:
  `GET /api/billing/entitlements` → `GET /api/billing/passes`; `POST /api/admin/users/{id}/entitlements` →
  `POST /api/admin/users/{id}/passes`; `POST /api/admin/entitlements/{id}/revoke` → `POST /api/admin/passes/{id}/revoke`;
  `POST /api/audience/{key}` → `POST /api/audiences/{key}/viewers`; `GET /api/audio/{id}` → `GET /api/voice-lines/{id}`.
  Фронтенд обновлён вместе с сервером.
- Протокол WebSocket: пустые поля больше не отправляются как `null` ни в одном сообщении (раньше пять видов частей
  состояния отправляли `null`, остальные опускали поле). Клиенты и так считали эти поля необязательными.
- `GameEngineService` (1733 строки) разделён: координатор (879 строк) и потоки `LobbyFlow`, `IntakeFlow`, `RoundFlow`,
  `VotingFlow`, `FinaleFlow`.
- SQL только в репозиториях модуля-владельца таблицы; отчёты админки собирают данные из них. Новые
  `AppSettingRepository`, `PassLogRepository`.
- Контракты API — отдельными файлами в пакетах `…/api` и `game/protocol`, с суффиксами `Request`, `Response`, `View`;
  ответы, которые были нетипизированными словарями, получили типы (форма JSON прежняя).
- Пакеты: почта — в `mail`, флаги — в `settings`, HTTP-обвязка — в `web`.
- Имена: исключения оканчиваются на `Exception`, компоненты — в единственном числе, `EntitlementsController` →
  `PassController`, `AudioController` → `VoiceLineController`, `IntegrationTest` → `AbstractIntegrationTest`;
  полные имена классов в коде заменены импортами.
- БД (миграция V6): `ai_call.is_free_game` → `is_free`, `entitlement.granted_by_admin` → `is_granted_by_admin`; все
  ограничения названы по схеме `pk_`/`fk_`/`ck_`/`ux_` + таблица + поля.
- Интеграционные тесты (`*IT`) запускает Failsafe в фазе `verify`; фаза `test` — только модульные, за секунды.
- Фронтенд: сцены общего экрана и телефона разложены по файлам в PascalCase (`pages/screen/scenes/`,
  `pages/play/scenes/`); общие функции админки — в `format.ts` и `Pagination.tsx`.
- Весь код переформатирован: Java — Spotless (palantir-java-format), TypeScript и CSS — Prettier.

### Added
- `frontend/src/lib/api/contract.gen.ts` — типы контракта, генерируемые из Java (`ContractTypesTest`); сборка падает,
  если файл устарел, а типы фронтенда сверяются с ним по полям (`contract.test.ts`).
- Проверки соглашений: формат кода (Spotless, Prettier) и 11 правил checkstyle для имён и порядка импортов — в
  `verify`; имена ограничений, индексов и булевых полей — в `SchemaIT`; отсутствие `null` в сообщениях протокола — в
  `SocketProtocolIT`.
- `docs/CONVENTIONS.md` — полный свод соглашений; `.env.example` описывает все переменные, включая лимиты комнаты и
  адреса API поставщиков.
- `docs/CODE_INSPECTION.md` — инспекция структуры и наименований.

### Deprecated
- `COOKIE_SECURE` и `SUPPORT_EMAIL`: используйте `APP_COOKIE_SECURE` и `APP_SUPPORT_EMAIL`. Старые имена пока работают.

### Fixed

## [0.7.0] — 2026-09-23

### Added
- Отправка писем через SMTP: `MAIL_PROVIDER=smtp` с переменными `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY` (`starttls`,
  `ssl`, `none`), `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_TIMEOUT`. Подходит для Gmail (с паролем приложения),

### Changed
- Неизвестное значение `MAIL_PROVIDER` останавливает сервер при старте с понятным сообщением (раньше — невнятной
  ошибкой о недостающем бине).

## [0.6.1] — 2026-09-23

### Fixed
- Вход через Google в локальной разработке заканчивался ошибкой `NOT_FOUND` на `http://localhost:8080/auth/callback`.
  Прокси дев-сервера Vite в короткой записи подменял заголовок `Host` на адрес бэкенда, поэтому приложение отправляло
  Google адрес возврата с `:8080`, где фронтенд в дев-режиме не отдаётся. Прокси теперь сохраняет `Host`, а после входа
  через Google (и при его ошибке) бэкенд перенаправляет на `APP_PUBLIC_URL`, какой бы хост ни принял ответ Google.
  В `.env.example` уточнено, какие адреса возврата регистрировать в Google.

## [0.6.0] — 2026-09-23

### Added

### Changed
- Ошибка Anthropic записывается с причиной из ответа, например `Anthropic HTTP 400: invalid_request_error: Your credit
  balance is too low…`, а не только с кодом.

### Fixed
- Команды в README не работали в Windows PowerShell 5.1: там нет `&&`, bash-синтаксиса переменных окружения
  (`VAR=value команда`) и `./mvnw`, а параметры Maven с точкой разрезаются. Теперь у каждой команды есть вариант для
  bash и для PowerShell.

## [0.2.0] — 2026-09-22

### Security
- P0: в режиме стримера скрытый код комнаты попадал в трансляцию через ссылку для зрителей, а копии экрана получали
  ссылку на вход. Любой зритель мог войти игроком. Теперь у зрителей отдельный ключ, а ссылку на вход получает только
  экран владельца.
- P0: неограниченная очередь отправки WebSocket позволяла исчерпать память сервера клиентами, которые не читают сокет.
  Теперь на соединение не больше 1 МБ неотправленных данных; при превышении клиент отключается с кодом 4408,
  переподключается и получает свежее состояние.

### Changed
- **Breaking:** зрители входят по ключу: `POST /api/audience/{key}` и ссылка `/w/{key}`. `POST /api/rooms/{code}/audience`
  удалён. `GET /api/rooms/{code}` возвращает `audienceKey` для комнат стримера.

### Added
- `docs/AUDIT.md` — аудит по 50 точкам с приоритетами.
- Подсказка стримеру включить полноэкранный режим, когда код скрыт.
